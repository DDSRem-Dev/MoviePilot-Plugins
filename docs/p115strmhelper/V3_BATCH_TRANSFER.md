# V3 整理接管：持久任务内的批量执行

本实现采用方案 A，适用于 `plugins.v3/p115strmhelper`。开启「接管网盘整理」，存储模块选择「115网盘Plus」后，同账号文件移动、复制和重命名仍可合并为批量网盘请求

V2 的行为参考保留在 [BATCH_TRANSFER_DESIGN.md](BATCH_TRANSFER_DESIGN.md)。V2 源码不变；V3 不再使用独立任务队列接收后立即返回成功

## 执行流程

1. 关联模式在请求阶段发现同目录匹配的字幕、音轨，复用宿主过滤、媒体归属及手动季集上下文；关闭关联模式则使用宿主原始候选规则
2. MoviePilot 为每个文件分别创建原生持久任务，完成媒体识别、目标命名、计划冻结和租约领取；插件给符合条件的计划增加批量标记
3. 每个任务继续执行宿主覆盖策略、插件拦截和目标目录准备
4. 原任务登记持久步骤，然后等待批量协调器。协调器按存储实例、动作和目标目录合并请求，默认等待 0.25 秒，每批最多 500 项
5. 逐文件确认实际结果，完成落地、重命名步骤后，再交回原宿主任务
6. 宿主逐任务原子提交历史、任务终态与完成事件。主视频、字幕、音轨各自保留任务身份；通知、刮削继续使用原宿主任务与作业聚合

宿主只有一个常规整理 worker 时，插件会临时增加运行宿主原生队列循环的辅助 worker，使多个原任务能进入同一批请求。辅助 worker 只领取已知来源、目标均为同一 115 存储的影视移动或复制任务：媒体类型可来自已识别信息、手动指定类型或宿主文件名解析结果，尚未区分电影／电视剧的影视解析对象也可进入原生识别流程。音乐、其他方式及目标尚未确定的任务留给宿主常规 worker

新任务入队和已有任务开始执行时都会检查是否需要增加辅助 worker，因此启用或重载接管后，已在宿主队列中的任务也能参与批量执行。合并范围仍受目标目录和就绪时间影响，不保证整个整理请求只发送一次网盘操作

## 保留的功能

| 功能 | V3 行为 |
| --- | --- |
| 批量移动 | 合并 `fs_move`，实际确认目标，保留原文件 ID 和 pickcode |
| 批量复制 | 合并 `fs_copy`，按目标目录基线、新 ID、名称、大小和 SHA1 确认副本，使用副本的 pickcode |
| 批量重命名 | 独立持久步骤合并 `fs_rename`，重命名失败后不会重新移动或复制 |
| 关联字幕／音轨 | 保留同目录自动发现附件的自定义能力；使用 V3 过滤、媒体归属、命名及繁简字幕标签规则，每个附件独立入队 |
| 独立字幕／音轨 | 两种模式都保留显式选择的附件，由宿主独立整理，不因开启关联模式直接跳过 |
| 覆盖与扩展事件 | 执行宿主 `never`、`size`、`always`、`latest` 及覆盖检查、整理拦截事件 |
| 预览 | 使用宿主预览结果，不写云端、不创建执行步骤；关联模式可能读取同目录候选文件 |
| 历史和事件 | 每个文件以自己的持久任务记录历史和事件，失败附件可通过原生历史重试 |
| 汇总通知 | 使用宿主电影／剧集汇总；未配置访问域名时省略空链接按钮，保留图文和集数 |
| 源目录清理 | 成功移动后按目录去重扫描和复核，串行删除最外层可清理目录；同批重复收尾不重复查询，不删除下载器种子或修改种子状态 |
| 缓存 | 更新宿主实际选中的存储实例，不另外构造 P115Api |
| 非接管任务 | 其他存储、目录、音乐及其他整理方式继续走宿主原流程 |

主视频和附件作为不同任务进入同一个批量协调器，仍能合并网盘请求；不保证单个视频及其全部附件恰好合并在一次请求中。关闭重命名时保留原文件名，排除规则、隐藏文件过滤及附件归属交给宿主规则处理

## 失败与恢复

- **响应丢失或进程中断**：先观察真实云端状态，再决定完成步骤或重试，不直接重复复制
- **移动／复制成功，重命名失败**：保留落地文件身份，只恢复尚未完成的步骤
- **批量请求部分成功**：按文件分别确认，成功项继续，确定未生效的失败项交给宿主重试
- **无法确认结果或存在多个匹配副本**：进入宿主人工复核，避免自动创建更多副本
- **租约失效**：旧任务不能登记新步骤；发起批量请求前再次检查原任务租约。宿主确认终态已提交后立即停止该任务的本地续租，清理和通知耗时不再延长续租范围
- **源文件消失或源目录查询失败**：只阻止受影响文件，其他已确认源身份的文件继续批量执行
- **关联文件最终失败**：新任务中，主视频成功不受附件失败影响，继续完成历史、事件、成功通知和刮削；失败附件保留自己的任务 ID，原生重试只执行该附件
- **历史／事件提交失败**：同一事务回滚，宿主重放结算；不因数据库失败再次操作云端文件
- **停止时仍有任务**：等待原任务和在途批次退出后再解除补丁，超时保留运行对象，不提前宣告停止完成

升级前已冻结的多文件关联计划仍按旧格式恢复，保留逐文件执行证据及原子结算，不自动迁移为新独立任务；尚未执行的旧附件跳过计划恢复为真实执行。旧格式兼容所需的执行、验证和结算代码继续保留，测试使用显式旧计划夹具，不再依赖已删除的旧匹配算法

已有批量持久计划需要此插件的批量扩展才能恢复。存在待重试或人工复核任务时，应先处理这些任务，再关闭整理接管或卸载插件

## 代码位置

| 文件 | 职责 |
| --- | --- |
| `patch/transfer_chain.py` | 安装和恢复宿主补丁、传递原任务上下文、锁定冲突路径 |
| `helper/transfer/batch.py` | 收集和合并操作，逐文件返回真实结果 |
| `helper/transfer/workers.py` | 临时运行宿主原生 worker |
| `helper/transfer/linked_candidates.py` | 请求阶段发现关联附件，交回宿主创建独立任务 |
| `helper/transfer/planning.py` | 标记批量计划、执行原生前置策略并兼容旧计划恢复 |
| `helper/transfer/durable.py` | 目标基线、移动／复制、重命名及结果确认 |
| `helper/transfer/validation.py` | 仅允许冻结计划和成功步骤证据派生的扩展操作 |
| `helper/transfer/settlement.py` | 兼容旧多文件计划的原子结算、失败证据与事件 |
| `helper/transfer/file_types.py` | 旧计划结算中的字幕事件分类 |
| `helper/transfer/cache_updater.py` | 更新和移除实际存储实例的文件缓存 |
| `helper/transfer/cleanup.py` | 按原边界清理源目录 |

实现使用经过宿主源码核对的内部 patch，不需要修改 MoviePilot 源码，也不增加插件数据库迁移。上游整理内部契约变化时，由真实宿主加载测试和批量契约测试发现不兼容

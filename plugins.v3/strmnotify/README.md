# STRM逐条通知

MoviePilot V3 独立通知插件。监控指定目录内新出现的 STRM，等待同名 NFO 和远程封面，通过 MoviePilot 通知渠道发送媒体标题、年份、演员、标签、文件名和封面。

## 设置

- 启用插件：默认关闭
- 监控目录：MP 容器内绝对路径，每行一个；重叠子目录自动合并
- 扫描间隔：默认 30 秒，范围 10–3600 秒
- 等待 NFO/封面：默认 120 秒，范围 10–86400 秒；NFO 有标题但封面尚未生成时，在等待窗口内按扫描间隔轮询；超时仍无封面则发送无图通知，超时无有效 NFO 则跳过
- 每轮最多通知数：默认 10，范围 1–100；多个目录按待处理时间公平轮询，避免前一个目录长期占满配额
- 通知渠道：默认跟随 MP 配置，也可选择渠道；请在 MP 通知设置里允许插件消息
- 封面、年份、演员、标签、文件名：分别可开关

## 行为边界

首次成功扫描只建立存量基线，不补发历史文件。新增目录同样先建立基线；轮询期间创建后又删除的文件无法发现。已知路径被覆盖不再次发送；只有扫描观察到路径删除、之后重新出现才视为新增。通知记录和待处理队列通过 MP 插件数据持久化，重启继续处理。状态未变化的扫描不写数据库；发现新文件、通知提交成功或 NFO 超时后保存状态。

优先使用同名 `.nfo`；仅当目录中只有一个 STRM 时允许使用 `movie.nfo`。不会随机使用其他 NFO。支持 movie、episodedetails、musicvideo。NFO 至少稳定 2 秒且须有标题；不完整 XML 等待下一轮，不加载外部实体。本地封面路径不会作为远程图片发送。启用封面通知时，NFO 先写入而封面后生成的情况会保留在待处理队列中，直到封面出现或等待窗口结束。

通知中的“已入库”表示 STRM 与 NFO 已就绪，不代表 Plex/Emby 已完成扫描。轮询不读取 STRM 内的播放 URL，不访问云盘、不删除媒体文件，不需要云盘 Cookie。启用前需停用其他插件的同类逐条通知，否则会重复。

通知提交给 MP 后立即保存去重状态；MP 不提供最终渠道送达确认。如果进程在提交通知后、保存记录前异常退出，可能重发。插件不能保证端到端恰好一次送达。目录暂不可用或扫描失败时保留记录；正常可读但为空的目录按文件已删除处理。扫描时文件刚好被整理器移动会跳过本次观察，不会让整棵目录失效。

## 验证

在插件目录运行 `python -m unittest discover -s tests -p test_engine.py`。测试只使用临时文件，不连接真实服务。已另在隔离 MP V3 环境验证加载、表单、服务注册、限量发送、持久化去重及停用逻辑，通知发送和宿主基类初始化使用 mock；可在已配置测试依赖的隔离 MP 源码环境执行 `tests/host_smoke.py` 重现。
